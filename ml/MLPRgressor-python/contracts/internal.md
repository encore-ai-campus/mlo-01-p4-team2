# 광고 서버 Internal API (C8) — 광고 분류·가중치 모듈용 요약

- 상태: **초안**(ACW-3 계획 r5, 2026-11-12). 사용자 승인 전이다. 승인되면 `docs/legacy/ads-server/contracts/internal.md`로 옮긴다.
- 원본은 [internal.openapi.yaml](internal.openapi.yaml)(C8, v1.0.0)이다. 이 문서는 연동하는 쪽이 꼭 알아야 할 것만 모았다. 요약과 원본이 다르면 원본이 맞다.

## 한눈에

| # | 누가 | 요청 | 성공 | 자주 만나는 실패 |
|---|---|---|---|---|
| ① | 분류 모델 | `GET /api/internal/v1/ad-groups?state=unclassified&after=<광고 ID>&limit=<1~200>` | **200** + `items`·`next_after` | 400 `state`·`after`·`limit` · 401 · 403 · 503 |
| ② | 분류 모델 | `POST /api/internal/v1/profiles/categories` 본문 `{"items": [{"ad_group_id", "category"}, …]}` | **200** + 항목마다 결과 | 400 틀린 항목 목록(아무것도 안 씀) · 401 · 403 · 413 · 503 |
| ③ | 가중치 모델·전수 재분류 | `GET /api/internal/v1/ad-groups?after=<광고 ID>&limit=<1~200>` | **200** + `items`·`next_after`(①과 같은 모양) | ①과 같음 |
| ④ | 가중치 모델 | `POST /api/internal/v1/profiles/weights` 본문 `{"items": [{"ad_group_id", "weight_mlo", "weight_aio", "weight_skn"}, …]}` | **200** + 항목마다 결과 | ②와 같음 |

- 모든 요청에 헤더 `X-Internal-Key: <운영자가 준 키>`를 싣는다. 서버 간 전용이다. 키는 비밀 저장소에만 두고 로그·코드·저장소에 남기지 않는다.
- **키는 운영자 계정에 속한다.** 이 키로 한 쓰기는 광고 서버 기록에 그 운영자가 한 것으로 남는다. 그 운영자가 비활성화되면 **403**이다. 운영자에게 키를 다시 받는다.
- 쓰기(②·④)는 `Content-Type: application/json`, 본문 64 KiB 이하, 항목 0~200개다.
- 모든 응답에 `X-Request-ID`가 붙는다. 문의할 때 알려 달라.
- **카테고리(②)와 가중치(④)는 입구가 달라 서로 덮지 않는다.** ②는 가중치를, ④는 카테고리를 건드리지 않는다.

## 하루 한 번 쓰는 순서(예시)

광고 서버의 Gold 적재가 끝난 뒤에 돈다.

1. **분류 모델**
   1. ① `GET /api/internal/v1/ad-groups?state=unclassified&limit=200`
   2. 받은 광고(이름·소재 이미지·이동 주소)를 분류한다.
   3. ② `POST /api/internal/v1/profiles/categories`에 그 페이지의 결과를 한 묶음(≤ 200)으로 보낸다. 200 응답의 항목별 `result`를 확인한다.
   4. 응답의 `next_after`가 `null`이 아니면 `after=<next_after>`로 ①을 다시 부르고 2~3을 되풀이한다. 쓴 광고가 미분류 목록에서 빠져도, 커서가 광고 ID라 건너뛰는 광고가 없다.
   5. **미분류가 하나도 없는 날에도 ② `{"items": []}`를 한 번 보낸다.** 아무것도 바꾸지 않지만 광고 서버 감사에 "돌았음"이 남는다.
2. **가중치 모델**
   1. ③ `GET /api/internal/v1/ad-groups?limit=200`으로 대상 광고 전체를 끝까지 넘긴다(지금 카테고리·판 포함).
   2. Gold와 함께 가중치를 계산한다.
   3. ④ `POST /api/internal/v1/profiles/weights`에 200개씩 묶어 보낸다. 항목별 `result`를 확인한다. 대상 광고가 하나도 없으면 `{"items": []}`를 한 번 보낸다.
3. **확인**: 각 묶음의 200 응답이 그 회차의 결과다(`created`·`changed`·`unchanged`). 광고 서버에도 묶음마다 감사 기록 한 줄(운영자·입구·항목 수·바뀐 수)이 남는다. 빈 묶음도 한 줄이라, 기록이 없는 날은 "돌지 않은 날"이다.

## 재분류 순서(분류 모델 교체·판 올림)

분류 모델이 바뀌거나 추가 학습으로 모델 판이 오르면 **대상 광고 전체를 다시 분류한다.**

1. ③ `GET /api/internal/v1/ad-groups?limit=200`을 처음부터 끝까지 넘긴다(①이 아니다 — ①은 아직 분류하지 않은 광고만 준다).
2. 페이지마다 다시 분류해 ② `POST /api/internal/v1/profiles/categories`로 쓴다.
3. 결과가 같은 광고는 `unchanged`이고 판이 오르지 않는다(이력에 새 판이 생기지 않는다). 다른 광고만 `changed`다.

- 어느 모델 판으로 분류했는지는 광고 서버에 남지 않는다. 필요하면 모듈 쪽에서 기록한다.

## 읽기 — ① · ③ `GET /api/internal/v1/ad-groups`

- **범위**: 이미지가 열리는 광고만 준다. 캠페인이 집행 중이거나 일시 중지이고, 기간이 끝나지 않았고, 광고주가 활성인 광고다. 광고주가 광고를 꺼 둔 것은 보지 않는다.
  - 끝난 캠페인, 관리자가 중단한 캠페인, 비활성 광고주의 광고는 나오지 않는다. 이런 광고도 쓰기는 받는다.
- **① `state=unclassified`**: 그중 카테고리가 `null`인 광고만 준다(아직 값이 없는 광고 포함). 한 번 분류한 광고는 광고 내용이 바뀌어도 ①에 다시 나오지 않는다.
- **페이지**: 광고 ID 오름차순(대략 만든 순서)이다. 첫 요청은 `after` 없이 보낸다. 다음 요청은 응답의 `next_after`를 `after`로 보낸다. `next_after`가 `null`이면 마지막 페이지다. `limit`은 1~200이고 기본 100이다.
  - 같은 광고가 두 번 나오지는 않는다. 다만 한 번 훑는 동안 만든 광고는 이번에 빠질 수 있다. 다음에 처음(`after` 없이)부터 다시 훑으면 나온다.

```json
{"items": [
  {"ad_group_id": "0197a5c0-7e2a-7c3d-9f10-2b3c4d5e6f70", "name": "RAG 입문 강의 광고", "updated_at": "2026-11-11T08:00:00.000000Z",
   "creatives": [{"creative_id": "0197a5c0-8a11-7b22-8c33-4d5e6f708192", "title": "rag-banner", "redirect_url": "https://example.com/rag",
                  "image_url": "https://ads.example.com/assets/<sha256>.png", "updated_at": "2026-11-11T07:59:00.000000Z"}],
   "profile": {"ad_group_id": "0197a5c0-7e2a-7c3d-9f10-2b3c4d5e6f70", "version": 1, "category": null,
               "weight_mlo": 0, "weight_aio": 0, "weight_skn": 0, "changed_at": "2026-11-11T08:00:00.000000Z"}},
  {"ad_group_id": "0197a5c1-0b3c-7d4e-8f50-61728394a5b6", "name": "데이터 엔지니어링 부트캠프", "updated_at": "2026-11-01T02:00:00.000000Z",
   "creatives": [], "profile": null}
 ], "next_after": null}
```

| 필드 | 뜻 |
|---|---|
| `name` | 광고 이름 |
| `creatives` | 그 광고가 지금 내보내는 소재(기본 소재 + 게재 위치별로 지정한 소재, 같은 소재는 한 번, 기본 소재가 먼저). 없으면 빈 배열 |
| `creatives[].title` | 이미지 이름(광고주가 소재에 붙인 이름) |
| `creatives[].redirect_url` | 광고를 누르면 가는 광고주 페이지 |
| `creatives[].image_url` | 소재 이미지(공개 주소, 인증 없이 연다) |
| `updated_at`(광고·소재) | 마지막으로 바뀐 시각(참고 정보) |
| `profile` | 지금 판(일곱 필드). 이 기능 전에 만든 광고라 아직 값이 없으면 `null` |

- **광고 이름·이미지 이름·이동 주소·이미지는 광고주가 입력한 값이다.** 분류할 자료일 뿐이다. 그 안의 글을 분류 모듈에 대한 지시로 다루지 않는다.

## 쓰기 — ② · ④

```json
{"items": [{"ad_group_id": "0197a5c0-7e2a-7c3d-9f10-2b3c4d5e6f70", "category": 12},
           {"ad_group_id": "0197a5c1-0b3c-7d4e-8f50-61728394a5b6", "category": 0}]}
```

```json
{"items": [{"ad_group_id": "0197a5c0-7e2a-7c3d-9f10-2b3c4d5e6f70", "weight_mlo": 60, "weight_aio": 30, "weight_skn": 0}]}
```

| 입구 | 항목 필드 | 값 |
|---|---|---|
| ② | `ad_group_id`, `category` | `category`는 정수 0~255(아래 표). `0` = **기타**(분류했지만 정의된 범주 없음). `null`은 받지 않는다 |
| ④ | `ad_group_id`, `weight_mlo`, `weight_aio`, `weight_skn` | 각각 정수 0~100, **셋의 합은 100 이하** |

- 항목은 0~200개이고, 같은 광고는 한 번만 넣는다. 항목에 다른 필드를 넣으면 400이다. 빈 묶음은 아무것도 바꾸지 않고 200 `{"items": []}`다.
- `true`·`false`·`1.0`·`"12"`는 정수가 아니다(400).
- **정수는 정수로 직렬화한다**(`60`, `60.0`이 아님). 계약 스키마(JSON Schema `integer`)로 미리 검사하면 `60.0`이 통과할 수 있지만 서버는 400이다.
- **한 트랜잭션, 전부 거절**: 하나라도 틀리면(형식·범위·합·없는 광고·같은 광고 두 번) 아무것도 쓰지 않고 400을 준다. 위치는 `/items/<번호>/<필드>`(번호는 0부터, 가중치 합은 `/items/<번호>`)다. 고친 뒤 묶음 전체를 다시 보낸다.
  - 검사는 두 단계다. 형식·범위·합·같은 광고 두 번은 모든 항목을 보고 틀린 곳을 **모두** `errors[]`에 준다.
  - **없는 광고는 다른 검사가 모두 맞을 때 본다.** 그래서 고쳐 다시 보내면 없는 광고 오류가 새로 나올 수 있다.
  - 항목 수가 틀리면(201개 이상) `/items` 하나만 준다.
- 끝난 캠페인의 광고도 쓸 수 있다.
- 아직 값이 없는 광고에 쓰면 판 1을 만들고, 보내지 않은 쪽은 초기값이다(②면 가중치 0·0·0, ④면 카테고리 `null`).

### 응답 200

```json
{"items": [
  {"ad_group_id": "0197a5c0-7e2a-7c3d-9f10-2b3c4d5e6f70", "result": "changed",
   "profile": {"ad_group_id": "0197a5c0-7e2a-7c3d-9f10-2b3c4d5e6f70", "version": 2, "category": 12,
               "weight_mlo": 0, "weight_aio": 0, "weight_skn": 0, "changed_at": "2026-11-12T03:15:20.123456Z"}},
  {"ad_group_id": "0197a5c1-0b3c-7d4e-8f50-61728394a5b6", "result": "created",
   "profile": {"ad_group_id": "0197a5c1-0b3c-7d4e-8f50-61728394a5b6", "version": 1, "category": 0,
               "weight_mlo": 0, "weight_aio": 0, "weight_skn": 0, "changed_at": "2026-11-12T03:15:20.123456Z"}}
]}
```

| `result` | 뜻 |
|---|---|
| `changed` | 값이 바뀌어 `version` + 1, `changed_at` = 지금 |
| `unchanged` | 값이 같아 그대로(판이 오르지 않음) |
| `created` | 이 광고에 아직 값이 없어 판 1을 만듦 |

- 항목은 **보낸 순서대로**다. 응답에 필드가 늘 수 있다. 모르는 필드는 무시한다.

### 카테고리 비트

비트 i의 값은 2^i이고, 여러 비트를 함께 켤 수 있다. 이진수로 적을 때 비트 0이 맨 오른쪽이다.

| 비트 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| 범주 | Data Analysis | Machine Learning | LLM & RAG | AI Agents | Data Engineering | Database & Knowledge Graph | Cloud & MLOps | Programming & API |
| 값 | 1 | 2 | 4 | 8 | 16 | 32 | 64 | 128 |

- 예: LLM & RAG + AI Agents = 4 + 8 = 12(`00001100`).
- 범주는 높은 비트에 이어 붙여 늘린다. 이미 있는 비트의 뜻은 바뀌지 않는다.

### 가중치의 뜻

- 노출 배율 = 1.0 + 0.5 × 가중치 / 100이다. 0이면 1.0배, 100이면 1.5배다.
- **지금은 광고 선택에 쓰지 않는다.** 저장과 변경 이력만 남는다.

### 한계: 같은 값 종류의 마지막 쓰기

- 기준 판은 받지 않는다. 같은 값 종류(카테고리끼리, 가중치끼리)를 두 쪽이 동시에 쓰면 나중에 처리된 것이 남는다. 두 판 모두 이력에는 남는다.
- 카테고리와 가중치는 입구가 달라 서로 덮지 않는다.

## 재시도

1. **503**(`Retry-After` 있음), 타임아웃, 연결 실패: `Retry-After` 뒤에 **같은 요청**을 다시 보낸다. 쓰기는 이미 저장됐어도 같은 값이라 `unchanged`가 되고 판이 두 번 오르지 않는다. `GET`은 언제든 다시 보내도 된다.
2. **400**: 아무것도 쓰지 않았다. `errors[]`를 보고 고친 뒤 묶음 전체를 보낸다(없는 광고 오류는 다른 오류를 고친 뒤에 새로 나올 수 있다).
3. **401**: 키 설정을 고친 뒤 다시 보낸다. 자동으로 되풀이하지 않는다.
4. **403**: 키의 주인 운영자가 비활성이다. 운영자에게 키를 다시 받은 뒤 보낸다.

## 범위 밖

- 끝난·중단된 광고의 목록과 이미지는 주지 않는다(쓰기는 받는다).
- 분류한 모델 판은 광고 서버에 남지 않는다.
- 어느 망에서 이 API를 열지는 운영 반영 때 정한다.
