# 가중치 모델 구현 라우팅

이 문서는 독립 Python 가중치 프로그램의 작업 순서와 통과 기준을 정한다.
문서 검토가 모두 끝나기 전에는 코드를 작성하거나 기존 초안을 반영하지 않는다.
각 구현 단계는 코드 검토, 검증, 테스트를 통과해야 다음 단계로 넘어간다.

## 1. 대상과 범위

- 최종 경로: `/Users/sindong-yeob/project/ml/MLPRgressor-python/`.
- 현재 작업 장소: 별도 임시 디렉터리. 검토되지 않은 기존 임시 코드는 참고 자료다.
- 결과물: Python 프로그램, 테스트, 환경 설정 예제, 실행 문서, 검토 기록.
- 제외: 자체 API 서버, 실행·완료 API, LLM, 직접 DB 접속, 운영 배포, GitHub 게시.
- 실제 광고 서버·S3에는 접속하지 않는다. 개발 검증에는 로컬 Delta와 모의 HTTP를 사용한다.
- `operation-server`와 `laya-python`의 코드는 바꾸지 않는다.
- 지정 경로 반영은 검토·검증·테스트가 끝난 파일에만 수행한다.

## 2. 변경하지 않을 계약

| 항목 | 확정 내용 |
|---|---|
| Gold | `creative_course_daily/v2`, 키 `kst_date × ad_group_id` |
| 대상일 | 실행 시 KST 어제 날짜. DB 시각은 UTC |
| 입력 | 과정별 CTR·CVR 6개와 category 비트 8개, 총14개 |
| 과정 순서 | MLO → AIO → SKN |
| 카테고리 | NULL 제외, 0은 기타. bit0이 이진수 맨 오른쪽 |
| 정상 입력 | confirmed=true, 유효 UUID, category 0~255, 비율6개가 유한한0~1 |
| NULL | 입력 NULL 행은 제외. 임의0 대체 없음 |
| 학습 정답 | `s=CTR*(1+4*CVR)`, 과정별 `y=s/sum(s)`. 전부0이면 `[0,0,0]` |
| 모델 | 최초 MLPRegressor 학습. 이후 어제 자료로 partial_fit |
| 출력 | 실제 정수3개, 각각0~100, 합계100이하 |
| 전송 | C8 GET `/ad-groups`, POST `/profiles/weights`만 사용 |
| 상태 변경 | DB·version·changed_at·outbox는 광고 서버가 처리 |
| 외부 설정 | `.env`로 API 주소·키·Gold 경로 주입. 비밀값을 저장소·로그에 남기지 않음 |

클릭수 입력, 표본 신뢰도 보정, 과거30일CVR정정 재학습, 밴딧은 Future work다.
정답 산식 모사를 실제 광고 성과 개선이나 최적 가중치 발견으로 설명하지 않는다.

## 3. 문서 작업 순서

후속 계획 파일은 각 단계에 들어갈 때 하나씩 작성한다.
이 표의 후속 경로는 예정 경로다. 전체 문서 최종 검토 전에는 모두 존재해야 한다.

| 순서 | 문서 | 검토 통과 뒤 다음 작업 |
|---|---|---|
| D0 | 현재 라우팅 문서 | CP01 계획 작성 |
| D1 | `checkpoints/CP01-data.md` | CP02 계획 작성 |
| D2 | `checkpoints/CP02-learning-state.md` | CP03 계획 작성 |
| D3 | `checkpoints/CP03-ads-client.md` | CP04 계획 작성 |
| D4 | `checkpoints/CP04-runner.md` | 전체 문서 최종 검토 |
| DF | 별도로 생성한 최종 문서 검토자 | 전체 PASS일 때만 CP01 구현 시작 |

문서 검토자는 한 명을 순차 재사용한다. 최종 문서 검토자는 별도로 생성한다.
FAIL이면 해당 문서만 수정하고 같은 검토자에게 재검토받는다.
검토 PASS 전에 다음 계획을 작성하거나 구현을 시작하지 않는다.

## 4. 구현 체크포인트

| 단계 | 책임 | 산출물과 범위 |
|---|---|---|
| CP01 | 데이터·설정·산식 | 환경 설정, Gold 날짜 필터, 입력14 검증, 정답·정수 변환, 단위 시험 |
| CP02 | 학습·영구 상태 | MLP 이어 학습, 버전별 모델·학습 이력, 환경 결합, 파일 잠금·원자 저장 |
| CP03 | C8 클라이언트 | 인증, 커서 읽기, 200개 묶음 쓰기, 응답·UUID·정수 검사, 오류 분류 |
| CP04 | 전체 실행 | CLI, 일별 상태 전이, 재시도·재개, 통계, 실행 문서, 통합 시험 |
| IF | 전체 구현 최종 검토 | 체크포인트 연결·누락 검토, 전체 검증·테스트, 지정 경로 최종 확인 |

체크포인트마다 아래 순서를 지킨다.

1. 승인된 해당 계획과 라우팅 문서를 읽는다.
2. 해당 범위의 코드와 테스트 코드를 작성한다.
3. 검토 서브 에이전트 한 명에게 코드와 호출 경로를 검토받는다.
4. PASS 후 정적·계약 검증을 수행한다.
5. 검증 후 해당 테스트와 필요한 기존 회귀 테스트를 실행한다.
6. 모두 통과한 파일과 증거만 지정 경로에 반영한다.
7. 라우팅 진행표와 검토 기록을 갱신하고 다음 체크포인트로 간다.

코드 수정으로 검토 내용이 달라지면 같은 검토자에게 변경분을 다시 검토받는다.
검증·테스트가 실패하면 그 단계에서 멈춘다. 수정 → 재검토 → 검증 → 테스트 순서로 돌아간다.
코드 검토자는 우선 읽기 검토를 수행한다. 실행 검증과 테스트는 PASS 이후 루트가 수행한다.

## 5. 실행·복구 원칙

- 스케줄러는 매일 KST22시에 한 번 실행한다. 프로그램이 재시도를 판단한다.
- 일시적 실패는 첫 시도를 포함해 최대3회 시도한다.
- 대기는 최소10분이다. Retry-After가 더 길면 더 오래 기다린다.
- 설정·인증·권한·요청 계약 오류는 자동 반복하지 않는다.
- 정상 NULL 제외로 유효행0개이면 추가 학습·추론을 하지 않는다. 불필요한 자동 반복도 하지 않는다.
- 빈 Gold 또는 미확정 행이 있으면 대상일 학습 전체를 보류하고 같은 날 재시도를 허용한다.
- 학습 보류는 모델과 학습 완료 지점을 전진시키지 않는다.
- 학습 성공 상태와 고정된 전송 결과를 저장한 뒤 API 쓰기를 시작한다.
- 같은 대상일의 전송 실패는 저장한 결과로 재개한다. 다시 학습하지 않는다.
- 날짜가 지난 미전송 결과는 자동 게시하지 않고 대체된 기록으로 남긴다.
- 재시도 대기가 KST 날짜를 넘으면 그날 자동 재시도를 중단한다.
- 실제 전송 직전에도 대상일 만료를 검사한다.
- 모델은 학습 성공마다 버전 파일로 보관한다. API 재전송으로 모델 버전을 올리지 않는다.
- API 주소·Gold 경로가 다르면 모델 로딩·네트워크 접근 전에 기존 상태 재사용을 막는다.
- 키만 교체했으면 같은 환경이다. 키를 모델·상태 파일에 저장하지 않는다.

## 6. 계약상 한계

정본은 `../contracts/internal.openapi.yaml`이다. `../contracts/internal.md`는 보조 설명이다.
참조 파일 상태는 Draft다. 이 작업에서 실제 API 제공 여부를 확인했다고 주장하지 않는다.

- 가중치 요청에는 ad_group_id와 세 가중치만 넣는다. source나 expected_version은 넣지 않는다.
- source=mlpregressor와 통계는 로컬 실행 기록에만 남긴다.
- C8은 기준version 검사가 없다. 동일 종류는 나중 쓰기가 남는다.
- 로컬 잠금은 같은 상태 저장소에서만 유효하다. 가중치 작성자는 한 곳으로 운영한다.
- category 재조회는 읽기와 쓰기 사이 변경을 원자적으로 막지 못한다.
- 실제 광고 선택에 가중치를 적용하는 기능은 이번 범위 밖이다.
