# CP04 전체 실행과 재시도 및 통합 검증

## 1. 진입과 종료

계획 작성은 CP03 계획 PASS 뒤에 한다.
구현은 전체 문서 최종 검토와 CP03 구현 게이트 완료 뒤에 한다.
main.py에서 승인된 세 단계의 기능을 연결한다. 자체 API 서버를 만들지 않는다.

종료 순서는 코드 검토 PASS → 정적·계약 검증 → 통합·전체 회귀 테스트다.
이후 전체 구현 최종 검토를 받고, 그 판정 후 최종 검증·테스트를 수행한다.
원격 실서버 시험이나 운영 배포는 하지 않는다.

## 2. 실행 인터페이스와 시간

- `python main.py`: 실제 설정으로 읽기·학습·API 전송을 한 번 수행한다.
- `python main.py --dry-run`: 읽기와 메모리 학습·예측만 한다. API POST와 모델 버전을 만들지 않는다.
- `--env-file`: 다른 환경 설정 파일의 명시적 위치를 받는다.
- 외부 스케줄러는 매일 KST22시에 이 명령을 실행한다. 프로그램에 상주 스케줄러를 넣지 않는다.
- 스케줄러 자동 등록은 하지 않는다. README에 Linux cron의 KST/UTC 차이를 명시한다.

한 프로세스의 시작 시각에서 KST 어제 날짜를 한 번 고정한다.
재시도 중에 학습 대상일을 몰래 바꾸지 않는다.
실행일의 다음 KST 자정이 이번 작업의 만료 시각이다.
만료 뒤에는 읽기·전송을 자동으로 계속하지 않고 보류로 종료한다.
각 네트워크 요청 전에도 만료 여부를 검사한다.
HTTP 요청이 이미 서버에 도달한 뒤의 처리 시각까지 원자적으로 통제한다고 주장하지 않는다.

## 3. 한 시도의 처리 순서

1. 설정을 검사하고 상태 잠금을 잡는다.
2. 환경·입력·정답·런타임을 검사한다. 불일치면 모델 로딩과 원격 호출 전에 중단한다.
3. 이미 전송까지 끝난 대상일이면 중복 학습·쓰기 없이 종료한다.
4. 이전 날짜의 미전송 결과가 있으면 대체 기록으로 보관한다. 자동 게시하지 않는다.
5. 같은 대상일의 미전송 결과가 있으면 Gold 재읽기·재학습 없이 전송을 재개한다.
6. 그 외에는 Gold snapshot과 어제 자료를 읽고 CP01 검사를 수행한다.
7. 원본0행·미확정은 일시적 학습 보류다. 유효0행은 자동 반복 없는 학습 보류다.
8. 정상 행이 있으면 현재 광고 목록을 끝까지 읽는다. API 인증 실패 전에는 학습하지 않는다.
9. 최초 또는 추가 학습 후 예측 전체를 검사한다.
10. 현재 광고 목록과 ad_group_id를 연결한다. profile NULL 또는 category 불일치면 전송에서 제외한다.
11. 모델 버전·학습 완료일·고정된 전송 후보를 CP02 순서로 저장한다.
12. 전송 시점의 목록을 다시 읽고, 아래 묶음 규칙으로 전송한다.
13. 전송 완료 상태와 결과 통계를 저장하고 종료한다.

학습 자료는 정상 Gold 행이다. 전송 자료는 현재 광고와의 교집합이다.
학습 제외와 전송 제외를 같은 수로 기록하지 않는다.

## 4. 묶음 고정과 재개

전송 후보는 모델을 게시할 때 고정한다.
각 후보는 ad_group_id, Gold category, 정수 가중치3개를 보관한다.

첫 전송 전에는 현재 목록과 category를 다시 비교한다.
아직 전송하지 않은 후보가 현재 대상에서 빠지거나 category가 다르면 제외 기록을 남긴다.
이후 첫 요청 본문과 해당 후보 구간의 끝 offset을 inflight 상태로 저장한다.
저장이 끝난 뒤에만 POST한다.

inflight에는 API로 보낼 items와 비교용 category, 구간 끝 위치를 보관한다.
비교용 정보는 API 본문에 넣지 않는다.
성공 응답을 검사한 뒤 result별 건수를 더하고 offset을 진행시킨다. inflight를 지우고 원자 저장한다.

통신 실패·503·응답 후 저장 실패가 발생하면 같은 inflight 본문을 사용한다.
재시도 때문에 새 예측·새 학습·새 모델 버전·다른 본문을 만들지 않는다.
상태 저장 전에 성공한 요청을 다시 보내면 C8의 동일 값 쓰기를 이용한다.
모든 묶음을 하나의 원격 트랜잭션으로 취급하지 않는다.

재시도 전 목록에서 inflight 광고가 사라지거나 category가 달라졌다면 POST하지 않는다.
inflight 일부를 빼서 다른 요청으로 재전송하지도 않는다.
해당 작업을 publish_state_changed 보류로 기록하고 같은 대상일 자동 게시를 막는다.
최초 요청이 저장됐을 수 있으므로 반영 여부를 미확정으로 남긴다. 이미 쓴 값을 되돌리지는 않는다.
다음 대상일에는 이 후보를 대체 기록으로 보관하고 새로운 대상일을 처리한다.

로컬 잠금은 같은 STATE_DIR만 보호한다. 다른 작성자의 쓰기 역전을 막을 수 없다.
가중치 작성자는 하나로 운영한다. 읽기 이후 category 변경을 원자적으로 막는 기능도 C8에는 없다.

## 5. 빈 묶음과 학습 보류

최종 전송 대상이 없으면 `{"items":[]}`를 전송해 감사 기록을 남긴다.
학습 보류에서도 빈 묶음과 제외 통계를 남기며 모델·학습 완료일은 바꾸지 않는다.
자동 재시도 중에는 빈 감사 전송을 성공한 뒤 같은 프로세스에서 다시 보내지 않는다.
프로세스 중단 직전 응답을 잃었다면 감사 기록이 중복될 수 있다. C8에 회차 키는 없다.
원격 읽기 자체가 실패한 경우에는 완료한 것처럼 빈 감사를 강제하지 않는다.

빈 감사가 실패하면 그 오류 분류를 따른다. 학습이 완료됐다고 기록하지 않는다.
정상 행이 있지만 현재 전송 대상이 없는 경우에는 모델 학습은 저장할 수 있다.
이 경우 학습 행 수와 전송0개를 구분한다.

## 6. 재시도와 종료 코드

재시도는 전체 실행부 한 곳에서만 수행한다. 첫 시도를 포함해 최대3회다.
실패한 시도 뒤 최소600초를 기다린다. Retry-After가 더 길면 더 오래 기다린다.
그 대기가 작업 만료 시각을 넘으면 기다렸다가 옛 자료를 전송하지 않고 보류로 종료한다.

| 상황 | 자동 반복 | 최종 종료 |
|---|---|---|
| 완료·이미 완료 | 없음 | 0 |
| Gold 원본0행·미확정 | 최대3회 | 보류75 |
| 연결·시간초과·응답 중단·503 | 최대3회 | 실패1 |
| 정상 NULL 제외로 유효0행 | 없음 | 보류75 |
| 설정·권한·인증·계약 오류 | 없음 | 실패1 |
| 잠금 경쟁·대상일 만료·상태 변경 보류 | 없음 | 보류75 |

SDK가 일시적 연결 실패로 분류할 수 있는 오류는 재시도한다.
분류할 수 없는 저장소 오류를 문자열 추측으로 일시적이라고 처리하지 않는다.
원시 SDK 예외를 출력하지 않고 실패 종류를 기록한다.

학습 전 실패는 기존 모델에서 다시 시작할 수 있다.
학습 성공 상태가 저장된 뒤에는 미전송 결과만 재개한다.
반복 상한을 넘었다고 모델·상태를 지우지 않는다.

## 7. 통계와 실행 문서

로컬 로그와 실행 기록에는 source=mlpregressor를 쓴다. 광고 API 요청에 넣지 않는다.
다음 값의 의미를 실행 문서와 시험에서 고정한다.

- planned_rows: 어제 Gold 원본 행 수.
- valid_rows: 입력 검사를 통과한 행 수.
- trained_rows: 성공적으로 게시한 모델에 사용한 정상 행 수. 커밋 전 보류는0이다.
- invalid_rows: 입력 검사에서 제외한 행 수.
- invalid_ad_group_ids: 식별 가능한 제외 광고UUID의 중복 없는 목록.
- unidentified_rows: 유효한 광고UUID가 없어 식별하지 못한 행 수.
- write_excluded_rows/IDs: 정상 학습 자료지만 현재 목록·category 조건 때문에 전송하지 않은 광고.
- write_counts: 확인한 응답의 created·changed·unchanged와 전송 중 제외 건수.

첫 changed 응답을 잃고 재시도하면 unchanged를 받을 수 있다.
따라서 write_counts를 서버에서 실제로 처음 변경된 광고 수라고 설명하지 않는다.
- 모델 버전·Gold version·대상일·상태·안전한 오류 코드·요청ID.

모든 정상 입력이 학습됐더라도 API 쓰기는 실패할 수 있다.
최종 실패 로그에도 학습 커밋 여부를 반영한다. 커밋 전 행 수를 실제 학습 성공으로 표시하지 않는다.

README에는 .env 작성, 설치, 실행, dry-run, 외부 예약, 종료 코드, 재실행, 환경 분리, 버전 보관을 적는다.
실제 .env·상태·모델·캐시·.venv는 설치 파일과 저장소에서 제외한다.
사용자 설정과 sibling 프로젝트를 덮어쓰지 않는다.

## 8. 검증과 통합 테스트

코드 검토 PASS 후 정적·계약 검증을 먼저 수행한다. 그다음 아래 테스트와 전체 회귀 시험을 수행한다.

1. 실제 로컬 Delta에서 어제만 읽고 실제 MLP 모델 버전을 저장한다.
2. 정상0행·미확정·빈 자료에서 신규·기존 모델이 그대로인지 확인한다.
3. 미확정→확정 같은 대상일 재실행이 최초 학습을 수행하는지 확인한다.
4. 같은 대상일 재실행에서 추가 학습·추가 모델 버전이 없는지 확인한다.
5. 최소201개 후보로 두 묶음을 만든다. 두 번째 묶음 실패 후 첫 묶음을 다시 학습·전송하지 않는지 확인한다.
6. 첫 POST 전에 inflight 저장 실패를 주입한다. 네트워크 쓰기가 없어야 한다.
7. 서버 반영 후 응답 유실, 성공 응답 후 로컬 저장 실패를 각각 주입한다. 같은 본문이 재전송돼야 한다.
8. 이전 날짜 pending과 새 Gold 실패를 조합한다. 옛 가중치를 자동 게시하면 실패다.
9. inflight 광고의 category 변경과 목록 제외를 주입한다. 다른 본문을 만들거나 자동 게시하면 실패다.
10. 최대3회·600초·더 긴 Retry-After·영구 오류 무반복·자정 경계를 가짜 시계와 sleep으로 검증한다.
11. 키 교체는 허용하고 API/Gold/endpoint 변경은 모델·네트워크 전에 거절하는지 확인한다.
12. CLI 종료0/75/1, source와 통계, 비밀값 비출력, dry-run 무쓰기 조건을 검증한다.

테스트는 실제 S3·광고 서버·운영 DB에 접속하지 않는다.
최종 구현 검토는 별도 검토자에게 전체 연결을 읽게 하고, PASS 뒤 최종 검증·테스트를 실행한다.
