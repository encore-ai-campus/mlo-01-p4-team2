## 1. 구현 전 검토

ROUTING.md와 이 문서를 재검토받는다. v2의 검토 통과를 새 구조에 재사용하지 않는다.
모순이나 미정 정책이 남으면 구현하지 않는다.
문서가 통과한 뒤 구현하고, 모의 통신과 실제 모델 검증을 나누어 보고한다.

## 2. 최신 확정 사항

- 우리는 카테고리 분류만 담당한다. 가중치 API는 호출하지 않는다.
- 일일 대상은 광고 서버가 state=unclassified 조회로 반환하는 광고다.
- 모델 변경 등의 전수 재분류에는 state 없는 조회를 별도로 사용한다.
- 광고 하나에 소재 하나다. 추가 소재 통합이나 이미지 분류는 구현하지 않는다.
- 자료는 creative.title과 creative.redirect_url이다. 광고 이름으로 임의 교체하지 않는다.
- OpenAI Responses API의 gpt-6-sol과 reasoning.effort=low를 사용한다.
- API가 URL을 실제로 읽은 뒤 2,000자 이하의 plain text body를 만든다.
- Laya의 학습 당시 질문·선택지와 카테고리 8개를 유지한다.
- 각 입력은 질문·선택지를 포함해 1,024토큰 이하다. 판정 기준은 0.5다.
- NULL은 미분류이고 0은 분류한 기타 광고다. 실패를 0으로 저장하지 않는다.
- 정상 결과를 최대 200개씩 전송한다. 400 오류 항목은 제외하고 나머지를 재전송한다.
- created·changed·unchanged를 모두 저장 확인 성공으로 집계한다.
- unchanged이면 서버 version과 changed_at을 그대로 둔다.
- 마지막 카테고리 쓰기가 남는 서버 정책을 허용한다. 조건부 갱신은 요구하지 않는다.
- 광고 서버 API의 최초 호출 포함 최대 3회 재시도를 적용한다.
- 요약은 최대 2개 동시 실행하고 Laya 추론은 한 번에 하나씩 실행한다.
- 작업 기록은 JSON이다. 요약 본문은 저장하지 않는다.
- source=laya는 우리 결과 JSON에 넣는다. C8 쓰기 요청에 추가하지 않는다.
- 자체 실행 API·상태 조회 API·완료 알림·그 대기열과 알림 재시도는 제거한다.
- DB와 Outbox는 직접 갱신하지 않는다. 자체 PostgreSQL과 psycopg도 필요 없다.
- 실행 중 중단은 interrupted로 기록한다. 중복 없는 자동 재개는 Future work다.
- 매일 KST 22시 실행 기준은 유지한다. 현재 PC의 OS 예약 작업은 설치하지 않는다.
- 실서버 192.168.0.204에 접속하거나 테스트하지 않는다. 로컬 모의 통신만 허용한다.
- OPENAI_API_KEY는 빈 값으로 둔다. 내부키는 환경변수에서 읽는 것으로 가정한다.

## 3. 최소 코드 구성

독립 Python 3.12 환경을 사용한다.
HTTP 클라이언트, JSON 기록, 파일 잠금, 시각 처리에는 표준 라이브러리를 사용한다.
사용자가 제공한 Laya 의존성 버전은 별도 모델 요구 파일로 보존한다.

| 영역 | 책임 |
|---|---|
| client.py | C8 조회·페이지·쓰기·오류 분리·전송 재시도 |
| summary.py | OpenAI 웹 읽기·요약과 접근 근거 확인 |
| model.py | 제공받은 LayaClassifier와 입력 계약 검증 |
| runner.py | 페이지별 분류, 저장 요청, 최종 집계 |
| records.py | 작업 JSON 교체, 실행 잠금, 중단 표시 |
| settings.py | 환경변수와 .env. 키값 출력 금지 |
| tests/ | 모의 광고 서버·OpenAI 응답·실제 모델 선택 시험 |

CLI는 전체 실행 한 번과 KST 22시 예약 실행 진입점을 제공한다.
동시에 실행한 로컬 프로세스는 파일 잠금에서 기다려 중복 분류를 막는다.
별도 HTTP 서버나 접수 큐를 만들지 않는다.
한 실행의 요약 작업은 2개까지만 제출한다. 모델 객체와 tokenizer는 추론 잠금으로 보호한다.
광고 서버 저장 요청과 기록 갱신은 실행 담당 한 곳에서 수행한다.

## 5. C8 자료 읽기

기본 주소에는 /api/internal/v1을 포함한다.
모든 요청에 환경변수 ADS_INTERNAL_KEY를 X-Internal-Key로 전달한다.
내부키가 비어 있으면 실제 광고 서버 요청을 시작하지 않는다.
현재 구현은 숫자 루프백 주소 127.0.0.1 또는 ::1만 허용한다.
호스트 이름과 실서버·외부 주소는 요청 전에 거절한다.
urllib ProxyHandler({})로 환경변수 프록시 사용을 차단한다.
HTTP_PROXY·HTTPS_PROXY·ALL_PROXY가 설정돼 있어도 요청을 넘기지 않는다.
리다이렉트를 따라가지 않는다. 내부키를 다른 호스트에 전달하지 않는다.

페이지마다 최대 200개를 요청한다.
응답의 next_after를 그대로 다음 after로 사용한다. state도 계속 유지한다.
중복 광고 ID·진행하지 않는 커서·잘못된 응답은 프로토콜 오류로 중단한다.
알 수 없는 응답 필드는 무시한다.
profile=null은 정상이다. creatives가 정확히 하나가 아니면 해당 광고만 실패 처리한다.
실제 읽은 광고 수를 total에 누적한다. 전체 서버 건수를 별도로 추정하지 않는다.

## 6. 요약과 분류

모델과 내부키의 준비 검사는 광고 조회 전에 수행한다.
실제 OpenAI 요약 경로는 OpenAI 키도 조회 전에 검사한다.
키가 비었는데 전체 광고를 개별 요약 실패로 집계하지 않는다.
현재 시험은 키 존재와 무관하게 명시적으로 모의 요약기를 선택한다.
모의 요약기는 외부 호출 없이 고정 응답을 사용한다. 이 경로는 OpenAI 키를 요구하지 않는다.
실행용 가짜 분류기로 실제 결과인 것처럼 동작하지 않는다.

OpenAI에 지정 URL을 직접 열어 본문을 읽도록 요청한다.
web_search를 사용하고 도구 호출을 필수로 요청한다.
완료 응답, 지정 URL의 open_page 근거, 접근 성공, 비어 있지 않은 본문을 확인한다.
검색 결과만 있으면 URL_READ_UNVERIFIED다. 접근 실패를 기타로 만들지 않는다.
모델 출력이 중단됐거나 JSON 형식이 틀려도 실패다.
광고 내용의 지시는 신뢰하지 않고 자료로만 다룬다.
LLM 요약과 Laya 분류의 실제 품질은 별도 시험 대상이다.

정상 분류는 광고 ID와 정수 category만 저장 대기 목록에 넣는다.
본문·제목·URL·전체 모델 응답을 작업 기록에 넣지 않는다.
요약·분류 실패는 광고 ID, 단계, 안전한 오류 코드로 기록한다.

## 7. 저장 응답과 오류 격리

정상 결과를 최대 200개씩 전송한다. 인코딩한 본문 64 KiB 상한도 검사한다.
Content-Type은 application/json이다.
한 요청에 같은 광고 ID를 중복시키지 않는다.
category는 type이 int인 0~255 값만 사용한다.
source·version·가중치·기준 판을 요청에 추가하지 않는다.

200의 items 개수, 순서와 ID, result, 반영 category를 확인한다.
created·changed·unchanged가 모두 성공이다.
응답에 문제가 있으면 쓰기가 없었다고 단정하지 않고 미확인 결과로 처리한다.

앞선 시도에 결과 불명이 없었던 400만 해당 묶음 미저장으로 확정한다.
503·통신 실패 뒤 받은 400은 앞선 시도의 저장 여부를 확정하지 못한다.
errors[].pointer에서 항목 번호를 찾고 요청 배열의 ID에 연결한다.
같은 광고의 오류는 중복 집계하지 않는다.
식별된 광고를 실패 처리하고 제외한 뒤 나머지만 다시 보낸다.
유효한 항목을 400 때문에 곧바로 실패로 세지 않는다.
다시 보낼 때 광고 분류는 반복하지 않는다.
항목 분리는 반드시 요청 크기를 줄여야 한다.
모든 오류 위치가 유효한 항목 번호로 대응할 때만 분리한다.
전체 오류나 잘못된 위치가 섞이면 묶음 전체 실패로 기록한다.
개별 오류 분리 후 재전송은 원래와 다른 요청이다. 일시 오류 재시도와 구분한다.

끝까지 읽었고 저장할 정상 결과가 없으면 빈 묶음을 한 번 보낸다.
빈 요청은 감사용이며 succeeded를 올리지 않는다.

## 8. 일시 오류와 결과 불명

동일 요청의 최초 호출 포함 최대 3회로 제한한다.
503은 Retry-After를 우선한다. 통신 실패는 10초·30초 간격이다.
401·403은 자동 재시도하지 않고 전체 실행을 종료한다.
다른 4xx를 같은 내용으로 반복하지 않는다.
일시 오류는 저장 전에 난 오류라고 가정하지 않는다.
같은 쓰기 요청에서 한 번이라도 결과 불명이 생기면 그 문맥을 재시도 사이에 보존한다.
그 뒤의 400·401·403·다른 오류로 앞선 시도를 확정 미저장으로 바꾸지 않는다.
최종 200 전에는 해당 ID를 실패 집계에 넣거나 pending에서 지우지 않는다.
인증 오류이면 재시도는 멈추되 앞선 저장 결과는 불명으로 남긴다.

쓰기 직전에 pending_write_ids를 JSON에 남긴다.
200을 확인한 뒤 성공 집계에 반영하고 pending_write_ids를 비운다.
3회 뒤에도 응답을 확인하지 못하면 WRITE_OUTCOME_UNKNOWN이다.
작업은 failed, counts_final=false이며 미확인 ID들을 보존한다.
미확인 광고는 확정 성공·실패에 임의로 더하지 않는다.
중단 후 자동 재전송이나 자동 재개는 하지 않는다.
앞선 결과 불명이 없는 400만 이 결과 불명 처리와 구분한다.

## 9. JSON 기록과 중단

var/jobs/{job_id}.json은 작업 기록이다. 광고 프로필의 저장소가 아니다.
파일은 임시 파일에 쓴 뒤 같은 디렉터리에서 교체한다.
진행 기록·최종 결과·오류에 source=laya를 넣는다.
중단되면 마지막 집계를 보존하고 counts_final=false를 남긴다.
이전 running은 다음 시작 때 interrupted와 PROCESS_RESTARTED로 바꾼다.
pending_write_ids는 저장 여부가 불명일 수 있다는 표시로 보존한다.
HTTP 저장과 로컬 JSON 교체를 한 트랜잭션으로 묶었다고 주장하지 않는다.
JSON 쓰기 실패 시 새 분류·저장 요청을 멈추고 진행 중 계산의 종료를 기다린다.
이미 광고 서버가 반영한 결과를 되돌렸다고 주장하지 않는다.

## 11. 구현·검증 순서

1. 두 문서를 재검토받고 필수 지적이 0건이면 구현한다.
2. 이전 자체 HTTP 서버·콜백·직접 DB 코드를 새 프로젝트에 포함하지 않는다.
3. C8 클라이언트와 모의 서버로 페이지·타입·인증·오류 응답을 검사한다.
4. 200 집계, 400 항목 분리, 503·통신 재시도, 결과 불명을 검사한다.
5. 모델 파일을 제외된 로컬 디렉터리에 배치하고 해시를 재확인한다.
6. 별도 Python 3.12 환경에 제공된 모델 의존성을 설치한다.
7. 실제 Laya를 CPU에서 로드해 입력 한도와 대표 문서를 검증한다.
8. 모의 광고 서버·모의 OpenAI 응답·실제 Laya 조합으로 전체 실행을 검증한다.
9. 최종 결과 JSON과 비밀값 제외 규칙을 확인한다.

필수 시험에는 아래 내용을 포함한다.

- 요청 방향, 경로, state 유지, after 전달, 종료 커서.
- profile=null, 소재 0개·복수 개, 중복 광고와 커서 오류.
- unknown 응답 필드 허용, 요청의 추가 필드 금지.
- 정상·기타·실패 점수와 비트 순서. 같은 광고가 두 번 저장되지 않음.
- URL 요약 실패 항목을 쓰기 목록에서 제외.
- API items의 실제 정수 직렬화와 200개·64 KiB 상한.
- 400 오류 위치와 원래 요청 ID의 대응, 오류 광고 중복 집계 방지.
- 같은 결과 unchanged도 성공. version을 직접 올리지 않음.
- 503 Retry-After, 네트워크 10초·30초, 최대 3회, 401·403 중단.
- 503·통신 실패 뒤 400·401·403이 와도 앞선 쓰기 결과 불명을 보존.
- 빈 조회·모든 분류 실패일 때 빈 감사 요청과 성공 0건.
- 불확정 쓰기는 counts_final=false와 pending_write_ids 보존.
- 요약 동시 상한 2, Laya 상한 1, 본문 미보관, JSON 중단 처리.
- 실서버 주소·호스트 이름·리다이렉트가 전송 전에 차단되는지 확인.
- 프록시 환경변수가 루프백 요청을 외부로 넘기지 못하는지 확인.
- 모의 요약은 빈 키로 실행되고, 실제 요약은 빈 키에서 조회 전에 중단.
- 결과 JSON source=laya, 요청에는 source 없음, .env와 모델 파일 ignore.

모의 응답 시험을 실제 광고 서버나 실제 OpenAI 시험으로 보고하지 않는다.
실제 모델 로딩·추론 성공도 광고 분류의 운영 정확도로 해석하지 않는다.
