## 저장 구조

- event_definition, event_progress, game_definition, game_play 네 테이블. 메인 회차 테이블이나 run_uuid는 추가하지 않았다.
- 실제 최신 `identity.User`의 UUID PK를 참조하며 별도 사용자 UUID를 만들지 않는다.
- game_play에는 시작 INSERT와 종료 UPDATE를 사용한다. 성공/실패/중단과 점수 전용 FINISHED를 구분한다.
- 검증·재전송 충돌 처리를 위해 게임 시작 조건과 결과 근거를 evidence JSON에 보관한다. FINISHED와 evidence는 참고 DRD의 제안에서 이번 구현에 보완한 항목이다.
- SQL 라운드 입력, 카드 선택, 토핑의 수집 좌표·시각, 코팅의 입력 시각을 검사한다. 브라우저에서 실행되는 게임이므로 전문적인 부정행위 방지나 조작 불가능성을 보장하는 구조는 아니다.
- 최종 전달 시 서버의 행사 행 잠금과 순번 중복 금지 제약을 사용한다. 제작만으로 최종 완료시키지 않는다.
- 일일 안내 노출만 기존 StoryRecord의 UI 전용 키로 보관한다. 이전 초안의 StoryProgress flags를 새 메인 진척도로 이전하지 않는다.
- 프리즈 시 진행 중 게임을 INTERRUPTED로 정리하고 확정된 단계는 유지한다. 기존 메타버스 프리즈의 자동 시각 예약은 설정하지 않았다. 메인 변경 API에는 기획서의 행사 기간·이용 시간 검사를 적용한다.
- 기존 Outbox나 제거된 식단 댓글은 복원하지 않았다. CDC 대상 확장·분석 파이프라인·경품 지급·이스터에그 구현은 이번 메인 미션 연결과 별도다.
