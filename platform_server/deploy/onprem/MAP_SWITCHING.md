# 기존맵·이벤트맵 전환 운영

아래 실행 명령은 `platform_server/`를 기준으로 한다.
현재 저장소의 작업 브랜치는 `dev`에서 만들고, PR도 `dev`로 올린다.
마지막 절은 이벤트맵 개발 당시의 브랜치 운영을 설명한다.

두 브랜치는 `feat/15`의 이동 역할·서비스 역할 배포 구성을 공통으로 사용한다.
운영에서는 한 번에 한 맵만 실행한다. PR 생성이나 병합은 자동 배포를 의미하지 않는다.

## 운영 데이터 유지

- 두 맵은 같은 PostgreSQL DB를 사용한다. 각 역할의 `POSTGRES_DB`는 같게 유지하고, `POSTGRES_HOST`는 같은 DB로 연결되는 실제 PostgreSQL 주소를 지정한다.
- 각 역할의 운영 환경 파일은 `/etc/playdata/movement.env`, `/etc/playdata/service.env`처럼 checkout 밖에 보관하고 재사용한다. 비밀키·허용 호스트·공개 Origin·DB 계정은 유지한다.
- Redis 이동·서비스 설정과 jobs의 단일 실행 정책을 유지한다. 기존맵과 이벤트맵 프로세스가 동시에 같은 Redis 상태를 공유하지 않도록 기존 역할을 모두 종료한 후 전환한다.
- 파일 저장 데이터는 각 PC에서 checkout 밖의 고정 `CAMPUS_DATA_DIR`로 유지하는 것을 권장한다. 이벤트 브랜치에 운영 `.env`, SQLite, 로그를 복사하지 않는다.
- 이벤트 스토리·이용 일시정지 추가 버전에는 `event_story.0001_initial`, `campus_control.0001_initial` 마이그레이션과 테이블 4개가 추가된다. 전환 전에 운영 DB를 백업하고 같은 서비스 DB에 마이그레이션을 적용한다. 기존맵 코드로 돌아갈 때 추가 테이블·기록을 삭제하거나 DB를 과거 백업으로 덮어쓰지 않는다. 운영 PostgreSQL에서의 적용·복귀는 별도 검증한다.

## 전환 순서

1. 기존맵·이벤트맵의 검증된 커밋 번호, 운영 설정 위치, DB 백업 위치를 기록한다.
2. 전환 안내 후 진행 중인 이동 저장을 마무리하고 이동 역할과 서비스 역할(jobs 포함)을 종료한다. 자동 재시작 서비스도 함께 관리한다.
3. 두 PC를 같은 대상 맵의 같은 검증 커밋으로 갱신한다. 한 PC만 다른 맵으로 바꾸지 않는다.
4. 이벤트맵 버전에서는 각 checkout의 `platform_server/`에서 `node frontend/tools/build-event-map.cjs`를 실행해 화면·서버 충돌 데이터를 같은 원본에서 생성한다. 기존맵에서는 이 명령을 실행하지 않는다.
5. 신규 앱 마이그레이션을 공용 서비스 DB에 한 번 적용한 뒤 기존 운영 환경 파일로 `deploy/onprem/run.py movement` 또는 `service`를 재시작한다. 서비스 역할은 정적 파일을 `collectstatic --clear`로 다시 수집한다.
6. 공개 HTTP·이동 WS·채팅 WS가 모두 대상 버전을 가리키는지 확인한다. 브라우저 캐시·기존 탭이 남지 않도록 새로고침을 안내한다. 버전 쿼리가 없는 정적 파일은 외부 캐시가 있다면 갱신도 확인한다.
7. 로그인·이동·층 전환·게시판·채팅·쪽지·학습·포인트 보존을 확인한 뒤 운영을 재개한다.
8. 이벤트 종료 시 기록한 기존맵 커밋으로 동일한 순서를 수행한다.

공개 주소와 외부 입구 경로는 유지할 수 있다. 실제 WSL·두 PC·외부 연결 검증은 배포 환경에서 별도로 수행한다.

## 위치와 이벤트 상태

- `last_position`은 맵별 저장이 아닌 계정당 한 개다. 복귀 시 이벤트 전 기존맵 위치를 별도로 복구하지 않는다.
- 현재 맵의 서버 충돌 검사로 가까운 이동 가능 지점 또는 스폰으로 보정한다. 맵 변경 전후 대표 위치를 검증한다.
- 이벤트의 빼빼로 잔량은 접속 중 상태다. 재접속·서버 재시작 시 빈손으로 초기화되며 기존 포인트를 차감하지 않는다.

## 이벤트맵 개발 당시 브랜치별 검토

기존맵 `feat/17`은 `feat/15`를 대상으로 일반 PR로 검토한다.
이벤트 통합·배포 브랜치 `event`는 이벤트 변경 전 `feat/15` 커밋 `8ea1246`에서 생성한다. 초기 이벤트 작업 `feat/18`은 `event`로 병합됐다. 후속 스토리·운영 제어 작업은 `feat/27`에서 `event`를 대상으로 PR로 검토한다.
이벤트 후속 작업은 `event`에서 작업 브랜치를 만들고 PR도 `event`를 대상으로 올린다.
`feat/18`과 `event`는 `feat/15`·`dev`·`main`에 병합하지 않는다. 이벤트 운영 시 검증된 `event` 커밋을 배포하고 종료 후 기존 운영 커밋으로 복귀한다.
공통 기능 변경은 자동으로 서로 반영되지 않는다. 필요한 수정은 별도로 검토·반영한다.
