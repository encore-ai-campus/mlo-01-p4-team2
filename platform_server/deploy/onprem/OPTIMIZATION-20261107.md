# event 최적화 반영 기준

- PostgreSQL 풀: 프로세스별 최소1·최대10, CONN_MAX_AGE=0, 성공·실패 시 풀 반환.
- 실행 구성: 이동4·서비스4·jobs1. 관리 연결을 포함해 DB 연결 여유를 확보한다.
- 이동·HTTP/채팅 Front의 새 연결 대기열 기본값128.
- 메인 상태·순위 조회의 반복 쓰기와 추가 조회를 줄였다.
- 메인·게임·레시피·학습은 쓰기 트랜잭션 종료 후 응답 상태를 읽는다.
- 응답 조회가 실패해도 저장을 유지한다. 재시도 시 최초 시각·순위·업적을 중복 생성하지 않는다.
- 이동·채팅 WS는 Python Front를 우회하고 두 Nginx를 경유한다.
- HTTP·HTML은 서비스 Front를 유지한다. 로그인 쿠키·Origin·Host를 보존한다.
- 이동은 least_conn, 서비스 HTTP·채팅은 쿠키 hash를 사용한다.

검증 목표는 100계정 시험에서502·504가0건인 것이다. 이번 시험은 해당 기준을 통과했다.
대기열50 조건에서도0건이었으므로 대기열 확대만의 효과라고 확정하지 않는다.
응답 속도는 API마다 다르며 전체 P95의 일관된 개선은 확인하지 못했다.

원본 보고서·측정 파일은 작업 디렉터리에 보존한다. 운영 배포 완료를 뜻하지 않는다.
WS 예외 종료 정리의 추가 수정은 별도 진행 중이며 이 반영분과 구분한다.

## 반영 전 검증

- 별도 PostgreSQL DB에서 메인·레시피·업적·미니게임·연결 풀 관련153개 검사 통과.
- 배포 실행기6개 검사 통과. 이동·서비스 대기열128과 WS 우회 경로를 포함한다.
- 이동·서비스·입구 Nginx 설정3종의 구문 검사 통과.
- Nginx 공유 영역은 ARM64 환경에서도 생성 가능한128k로 설정했다.
- 검증 로그는 /private/tmp/platform-event-integrate-20261107에 보존했다.
