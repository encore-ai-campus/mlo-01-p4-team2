# 이동 위치 저장 미니 배치

일반 위치 저장을 프로세스 메모리에서 최대 10명씩 묶습니다.
기존 5초 저장 기한을 유지하며, 10명이 찰 때까지 기다리지 않습니다.

## 저장 순서

1. 각 소켓이 기존 기한에 최신 위치를 복사합니다.
2. 프로세스의 준비된 요청을 최대 10개씩 가져옵니다.
3. 기존 DB 실행 스레드에서 각 사용자의 세션을 확인합니다.
4. Profile을 UUID 순서로 잠급니다.
5. 오래된 위치를 거르고 Position을 한 번에 갱신합니다.
6. 이동 이벤트는 기존 간격과 outbox 규칙을 따릅니다.

위치와 이벤트는 같은 트랜잭션에서 처리합니다.
실패하면 해당 묶음을 되돌리고, 최신 위치를 다음 저장에 남깁니다.
저장 도중 더 최신 이동이 들어와도 dirty 상태를 유지합니다.
누락된 Profile·Position은 기존 개별 복구 경로로 처리합니다.

층 이동·로그아웃·접속 종료는 기존 즉시 저장 경로를 유지합니다.
세션 확인, DB 스레드 수, 연결 풀, freeze 정책은 바꾸지 않습니다.
DB 스키마 변경과 새 의존성도 없습니다.

## 검사

최신 event `617e9b8` 기준 관련 검사 62개가 통과했습니다.
배치 저장 검사 19개를 추가했습니다.
10명 제한, 23명 분할, 세션 취소, 실패 복구, 최신 위치 보존을 확인합니다.
이벤트 표본 유지, 트랜잭션 롤백, 겹치는 배치의 잠금 순서도 확인합니다.
기존 느린 저장 검사는 새 배치 호출 경로를 지연시키도록 변경했습니다.

운영과 분리된 PostgreSQL 환경 변수를 지정한 뒤 실행합니다.

```sh
DJANGO_SETTINGS_MODULE=deploy.onprem.test_settings PYTHONPATH=backend:. \
python backend/manage.py test \
  tests.test_position_batch \
  campus.test_positions.PositionStorageTests \
  campus.test_load_reduction campus.test_socket_cleanup \
  campus.test_movement_work campus_control.test_movement_cache \
  --noinput
```

## 이전 혼합 부하 결과

운영 r4 원본과 배치 적용본에서 수행한 로컬 측정입니다.
이 PR의 최신 event 기준에서는 위 회귀 검사를 다시 수행했습니다.
최신 event 전체의 혼합 부하를 다시 실행한 결과는 아닙니다.

100명이 이동·채팅·게시판 읽기/쓰기·문제 제출·카드 게임을 동시에 실행했습니다.
각 실행은 같은 초기 데이터의 DB 복제본을 사용했습니다.
연결 증가 뒤 10초를 준비하고, 60초를 측정했습니다.
진행 중인 작업 흐름은 최대 60초간 마쳤습니다.

| 비교 | 원본 이동 간격 P95 | 배치 이동 간격 P95 | 위치 SQL/명: 원본→배치 |
|---|---:|---:|---:|
| a1→b1 | 253.0ms | 164.7ms | 9.32→5.78 |
| a2→b4 | 289.2ms | 256.1ms | 9.33→5.49 |

이동 간격 P95는 약 35%, 11% 줄었습니다.
위치 저장 경로의 SQL은 사용자당 약 38~41% 줄었습니다.
개선 폭이 일정하지 않으며, 운영 성능을 보장하지 않습니다.
SQL 수에는 세션 검사와 이벤트 작업을 포함하고, HTTP SQL은 제외합니다.

전체 실행 결과는 [summary.json](../loadtest/results/20261109-position-mini-batch/summary.json)에 있습니다.

- 원본과 적용본 모두 게시판 읽기에서 잠금 충돌이 발생했습니다.
- b2에서는 서비스 연결 풀의 30초 시간 초과가 발생했습니다.
- b2 결과는 정상 실행의 개선율에 섞지 않았습니다.
- b3는 테스트용 게임 승인 만료로 비교에서 제외했습니다.
- 승인을 갱신한 뒤 b4를 실행했습니다.
- 실패 실행과 시간 초과도 집계에 남겼습니다.
- 답안·보상 중복, 사용자·세션 혼선, 지갑 불일치는 검사에서 0건입니다.
- 각 실행의 사용자 100명 모두 측정 시작 이후 위치를 저장했습니다.

요청 지연은 측정 구간에 시작해 성공 응답을 받은 요청의 P95입니다.
오류와 채팅 수신 미확인은 별도로 집계했습니다.
HTTP 시간 초과는 서버의 저장 실패를 확정하지 않습니다.
DB 실행 대기에는 배치 메모리에서 기다린 시간이 포함되지 않습니다.

## 한계

한 묶음이 실패하면 최대 10명이 함께 재시도합니다.
서비스 연결 풀과 게시판 잠금 충돌은 이 변경으로 해결하지 않습니다.
로컬 DB는 전체 CPU 포화 상태가 아니었습니다.
운영과 Python·Redis 버전이 다릅니다.
Python Front, campus_jobs, Kafka 전송, 브라우저 렌더링 부하는 포함하지 않았습니다.
앱의 실제 서비스 API와 outbox 저장은 실행했습니다.
게임 선행 조건과 접근 승인은 테스트 fixture로 준비했습니다.
운영 배포와 실제 사용자 회선 검증은 수행하지 않았습니다.
