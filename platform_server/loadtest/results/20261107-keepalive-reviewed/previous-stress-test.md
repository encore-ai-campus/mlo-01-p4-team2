## 4. 조건과 근거

- 이동 4개·HTTP/채팅 4개·jobs 1개, Front 2개를 실행했습니다. Front 연결 대기열은 128입니다.
- PostgreSQL 17.7과 Redis를 사용했습니다. 프로세스별 DB 풀은 최소 1개·최대 10개입니다.
- HTTP는 Front와 내부 Nginx를 거칩니다. WebSocket은 Python Front를 우회하며 내부 Nginx를 유지합니다.
- 메인 선행 조건은 테스트 데이터로 준비했습니다. 100명이 처음부터 모든 게임을 자연스럽게 플레이한 검사는 아닙니다.
- 문제 은행 3,580개를 적재했습니다. 운영 시간만 열었고 게임 판정 시간은 변경하지 않았습니다.
- 새 요청 생성을 멈춘 뒤 최대 65초 동안 남은 응답을 기다렸습니다. 미확정 요청은 0건입니다.
- P95·P99는 정렬한 전체 표본의 95%·99% 위치를 올림해 계산했습니다.
- 일반 부하 종료 시 미발행 요청 카운터 4개는 요청 분모와 오류에서 제외했습니다.
- Chrome 응답 유실은 수신 후 fetch 예외를 주입했습니다. 별도로 응답 본문 폐기 후 복구도 확인했습니다.
- 의도적으로 본문을 폐기한 요청 1건은 별도 기능 검사입니다. 지연표에서는 제외했습니다.
- 같은 로컬 PC에서 서버와 부하 도구를 실행했습니다. 외부망·TLS·실제 광고 서버는 검증하지 않았습니다.
- 이전 실행 결과와 실행기 준비 오류도 별도로 보존했습니다. 이전 수치와 이번 수치를 섞지 않았습니다.
