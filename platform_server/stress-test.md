## 2. 응답 속도

단위는 ms입니다. 성공은 각 검사의 예상 응답 확인을 뜻하며, 신규 업적 지급 수가 아닙니다.
정상 처리는 거리·시간 제한 거절, 의도한 게임 실패·중단, 복구용 오류 주입입니다.
표에 집계한 요청의 미응답은 모두 0건입니다. P95·P99에는 수신한 오류 응답 시간도 포함합니다.

기존 실패 54개의 준비 상태·기대값을 수정했습니다. 최종 통과 로그에서 해당 54개 검사를 확인했습니다.
초기 테스트 환경의 패키지 누락은 새 전용 환경으로 해결했습니다.
Chrome 시작 단계·소켓 준비 조건도 수정했습니다. 준비 실패 기록과 원래 A1 원자료는 보존했습니다.

**남은 성능 문제:** 저장에 1초 지연을 주입하면 이동 상태 최대 간격이 380.54ms였습니다.
기존 300ms 기준을 넘었으며 실패 1건으로 유지했습니다. HTTP 오류나 논리 오류와 합산하지 않았습니다.

A1의 504 23건과 A2의 504 28건은 입구 Nginx→Front의 5초 연결 제한에서 발생했습니다.
A2의 502 75건은 내부 Nginx의 no live upstreams와 대응합니다.
내부 연결 실패로 모든 worker가 잠시 제외됐습니다. 경고 로그 줄 수를 실패 요청 수로 더하지 않았습니다.
DB 클라이언트 연결은 최대 51/100개였습니다. DB 연결 상한 초과는 관측하지 않았습니다.
개별 SYN 재사용 원인까지 이번 시험에서 다시 추적하지는 않았습니다.

### HTTP 연결 생성 근거

기능 시나리오 시간창의 HTTP만 집계했습니다. 각 셀은 도달 요청 수 / TCP 연결 수입니다.

| Front → 내부 Nginx | 6,615 / 6,615 | 6,700 / 200 | 6,700 / 200 | 6,415 / 6,415 |
| 내부 Nginx → backend | 6,615 / 6,615 | 6,700 / 187 | 6,700 / 188 | 6,340 / 6,340 |

실제 Daphne 채널과 Nginx 연결 ID로 확인했습니다. 연결 시간 0ms만으로 재사용을 판정하지 않았습니다.
테스트 프로세스·포트·컨테이너를 정리했습니다. 기존 DB 컨테이너도 원래 종료 상태로 복구했습니다.
측정 사본과 현재 소스의 불일치는 0건입니다. 근거 묶음에서 검사한 인증값 잔존도 0건입니다.

한 로컬 PC의 관측값입니다. AWS·실제 사설망·TLS·정적 파일 100계정 다운로드는 이번에 다시 측정하지 않았습니다.
